# 视频思维（combo 风格）：先想清楚，再动手

> 来源：video-thinking.md（13 集拆解沉淀）。目标时长 1–3 分钟；原片是 20 分钟以上的长视频，这里只保留可迁移的部分。
> 凡标"估计"的数值不是实测，实测以 comfort-rules.md 为准。

## 1. 底层命题

观众不是在"看视频"，而是在跟一个人把一件事想明白。画面的唯一职责：让"想明白"的成本最低。

1. **主播负责判断（论点），动效负责证明（证据）。** 每个画面都有明确目的，观众的眼睛不用自己找。
2. **模板固定、内容替换。** 字幕位置、底色、标签样式不变，眼睛不需要重新定位。
3. **节奏跟着语义，不跟着时间码。** 切点落在换句处，贴字落在说到那个词的时刻。

## 2. 选题 5 问（开写前必答）

| # | 问题 | 通过标准 | 不通过怎么办 |
|---|---|---|---|
| 1 | 能不能"证据化"？（录得出、画得出） | 至少有一个可演示的界面、一个可画的数字、或一个可对比的前后 | 降级为纯观点型（模板 B），证据只用关键词卡 + B-roll |
| 2 | 有没有"以前/现在"落差？ | 能写出"以前你得…，现在只需要…"，或"表面现象 → 背后原因" | 改角度，找落差 |
| 3 | 能不能拆成 3 个节点？ | 3 个好处 / 步骤 / 阶段（1 分钟可 2 个） | 合并或砍到 3 个以内 |
| 4 | 有没有一个反常识的数字或结论？ | 一个"没想到"的数，用作钩子或反转 | 没有就去找一个（实测、对比、占比） |
| 5 | 与观众切身相关吗？ | 效率、门槛、成本、钱、政策、立场之一 | 换成观众的利益点来讲 |

前三条不满足 → 1–3 分钟撑不起"主播 + 证据"的结构：改选题或降级。第 4、5 条缺失可以补救但要写进风险。

过了 5 问再加一问：**这条片能勾起观众哪 1–2 个「想」？**（纠正你、看结果、看翻车、辨真伪、给你支招、带入自己、证明自己，见 audience-triggers.md）一个都对不上就换角度。

## 3. 开头：3 秒内要有钩子

- 观众在 3 秒内决定划不划走。**不寒暄、不自我介绍、不放 Logo**；问候最多 1s，可晚到 30s 后。
- 钩子 = 让观众心里冒出自己的疑问，再由主播回答。句式只有五类：问句、反差、承诺、最高级数字、反转（填空模板见 hooks-and-copy.md）。
- 3 秒内必须出现**第一次画面变化**（贴字弹出或硬切）。
- 开头 20–30s 是全片最密的一段：≥5 刀、2–3 个贴字（观众尚未建立信任）。
- 钩子之后紧跟"定义 + 预告"：我要讲什么、你会得到什么。建立预期，后面的重复结构才可预测。
- 悬念类钩子必须兑现，兑现点放在结尾并回扣开头。

## 4. 结构：固定单元重复

- **教程型单元五拍**：主播引出（≈3s）→ 章节卡（≈2s）→ 案例/痛点一句 → 录屏演示（5–10s/界面）→ 主播一句总结（≈4s）。每单元 ≈25s。重复到第二次，观众就能预测下一步，认知负担下降，这就是"舒服"。
- **三连排比 + 抽象归纳**：三个同构例子让观众学会模式，随后一句归纳（三个形容词/三张图卡逐个点亮）。
- **总分总**：总览 → 逐项（每项固定三拍：痛点一句 → 界面或图 7–10s → 价值一句）→ 总结卡逐条点亮。
- **转折交给主播**：提问、转折、总结由主播大景承担；大景的位置就是结构的骨架。
- **反转放在 60–75% 处**，让注意力在中段再抬一次。
- **坦白不足**放在总结之后、呼吁之前，主播全屏说，用信任换行动。
- 每个数字单独成句，并给参照物。

## 5. 观众心理节奏

| 阶段 | 占比 | 手段 | 画面/组件 |
|---|---|---|---|
| 好奇 | 0–15% | 反问、反差、悬念、最高级数字、成品预览 | 夹头词、压暗 B-roll 标题、双药丸对比、新闻快切 |
| 理解 | 15–70% | 类比、演示、图解；固定单元重复；每个新概念先痛点再方案 | 录屏 + PIP + HUD、图表、关键词卡、章节卡 |
| 认同 | 70–90% | 实测数据、坦白不足、价值观句 | 大数字、对比卡、总结卡、宽银幕情绪段 |
| 行动 | 90–100% | 一句提问 + CTA，回扣开头 | 主播大景 + 夹头词 |

- 好奇→理解的切换点是"定义 + 预告"，约在 15–20% 处。
- 每个阶段结尾都用主播大景收束一次，让观众确认"我跟上了"。

## 6. 信息密度（量化）

| 维度 | 取值 |
|---|---|
| 语速 | 5.0–5.5 字/秒（含停顿实际 4.5–5）；数据型上限 6.0 |
| 字幕行 | 8–10 字/行（最长 14），1.7–2.3s/行 |
| 屏上文字面积 | 中位 1–2% |
| 屏上要素 | 中位 0–1 个视觉块；一屏 ≤1 主标题 + 3–4 要素 |
| 画面更换 | 每 2–3 句一个主画面，平均 4–7s |
| 新概念 | 每 10s ≤1 个，每句 ≤1 个新名词（估计） |
| 贴字停留 | ≥40 帧（1.3s），说完就走 |

三条操作规则：
1. **一个画面一个观点。** 想放第二个观点就换镜头，或用叠加贴字分步出现。
2. **画面分担口播。** 口播列举三件事，画面逐个弹出三个标签，眼睛永远只看当前这一个。
3. **大字替口播承重，小字替细节承重。** 关键词用 0.08–0.14H 大字，细节放进字幕或录屏里。

## 7. 句子角色 → 谁出镜（决策树）

先给每句话定 `role`，再定 `intent`（画面形式）。

| 句子角色 | 例（通用） | 谁承担 |
|---|---|---|
| 钩子/反问 | "你还在手写纪要吗？" | 主播（加夹头词） |
| 论点/转折 | "真正的重点来了" | 主播大景（可加 punch-in） |
| 总结/评价 | "它不是替代你，是帮你省时间" | 主播大景 + punch-in |
| 章节衔接 | "我们先看第一步" | 主播 2–4s，再接章节卡 |
| 事实 | 融资数额、新闻 | 截图拼贴、大数字 |
| 数字 | "准确率九成" | 大数字卡 |
| 流程/关系 | 步骤、资金流向 | 步骤卡、信息图（图表为 P2 未实现，见 remotion-pipeline.md） |
| 界面操作 | "把录音拖进去" | 录屏 + PIP + 标注 |
| 比喻/故事 | "像铁匠铺学徒" | B-roll（3D 卡通为可选，成本高） |
| 概念名词 | 新提出的概念 | 黑底关键词卡 |
| 情绪 | "卷学历、卷实习" | 宽银幕 B-roll + 大字 |

**决策树**
1. 这句话在"判断"吗？是 → 主播。
2. 这句话在"证明"吗？是 → 按 visual-mapping.md 映射表找画面。
3. 证明素材不够？降级成关键词卡 + 主播，**不要硬凑 B-roll**。

**四拍序列**（观点/解读型）：主播提问 → 关键词卡（1–4s，1 帧硬切）→ B-roll/3D 举例（3–10s）→ 主播总结。
**演示序列**：章节卡 → 录屏 + PIP（7–10s/界面）→ 主播小结。

## 8. 把 20 分钟压成 1–3 分钟

原则：**保骨架，不保数量。**

1. **保**：开场钩子、定义/预告、1 个完整单元（痛点 → 证据 → 价值）、1 个数字、结尾提问 + CTA。
2. **砍**：并列案例（三留一）、逐功能演示（留 1–2）、品牌故事、情怀段、口播广告、自我介绍。
3. **每类证据只留最强的一个**：一个录屏、一个数字、一个对比。
4. **时间预算（估计）**：钩子 8–12%｜定义/预告 8–12%｜单元合计 55–65%｜证据数字 8–10%｜总结 + CTA 12–15%。
5. **演示单元数公式**：`N = round((T − 42) / 25)`，每单元 25s，上限 5（T=60→1，90→2，120→3，180→5）。
6. **保留框架，不保留规模**：暗底、字幕、PIP、HUD、章节卡原样保留，只缩短每段时长。
7. **取舍顺序**：先删"可选"，再压"应当"，"必须"一条不能砍（见 comfort-rules.md 末尾分级）。
8. 开头仍保持最密；整体 14–18 刀/分，别因为短而加速到 25 以上。

## 9. Claude 的思考步骤（用户给选题后照做）

对应 SKILL.md 协作工作流的第 0–2 轮（原"步骤 0–7"），这里给细则；每步产出都先交用户确认（见 references/collaboration.md）：

**步骤 0 确认输入**：选题、目标时长（60/120/180s）、已有素材（录屏、截图、数据、Logo）、数字人工具、路径（A 剪映 / B Remotion）。缺素材先问，**不编造**。
**步骤 1 判定类型**：工具测评/教程 → 模板 A；观点/解读 → 模板 B；数据/事件 → 模板 C。依据：有无可演示界面、有无关键数字。
**步骤 2 主张与证据**：写一句话主张（观众看完应该相信什么）；列 ≤3 个证据并标素材来源；找出一个"反常识数字或反差"做钩子和反转素材。
**步骤 3 选钩子**：从 hooks-and-copy.md 选 1 种并填空，确保 3 秒内出现问句、反差或承诺。
**步骤 4 搭骨架**：按 templates.md 时间表放段落；按时长反推字数；演示型用 N 公式。
**步骤 5 逐句写口播并打标签**：每句 ≤20 字；写 `role` 与 `intent`；论点和转折给主播，证据给动效；关键词标 `marks`（level 2 贴字、level 1 重读）；每个数字单独成句。
**步骤 6 分配画面**：连续 2–3 句合并为一个主画面；检查大景是否每 15–20s 回来、无脸段 ≤10s、punch-in ≤2/分。
**步骤 7 排节奏**：前 20–30s 最密；之后"15s 紧 + 15–20s 松"循环；录屏镜头标出要推到的 UI 区域。

## 10. 风险提示

- lint 通过 ≠ 像他们：lint 只保证"不违反舒适规律"，气质靠主观 A/B 盲看。
- 数字人手势少：原片主播手势幅度大是"舒服"的一部分，数字人要用 punch-in 与夹头词补偿。
- 样本局限：13 集（博主A 9、博主B 4）；博主B 贴字统计离散大；原片无音频，配乐/音效为推测。
