# 口播融合口径（口播视频 + 高级动效）

用户 2026-10-19 看过 S1（宣传片）、S2（口播融合）后的结论：「基本上不是我想要的东西」。本文把他要的口径写死，做口播片前必读。来源：用户反馈记忆 `feedback-showcase-review-2026-10-19`；示例项目 骨架观察见第 2 节。

## 1. 用户的评价（现状）
| 对象 | 评价 | 怎么办 |
|---|---|---|
| 标题字（设计师标题 13 款） | **不错，已认可** | 作为动效水准的基线：口播片里所有元素的动效和设计升级到这个水准 |
| 图表 / 仪表盘动效 | 「不行」 | 要做设计层面的真功夫，不是占位级；见 `block-upgrade-backlog.md` 的图表升级项 |
| 图标本身 | 「太 low」（图标的**动效**没问题） | 升级图标本体（2.5D 等距/多色/渐变/玻璃层/投影），保留现有动效预设；见 backlog |
| S2 口播融合 | **被否** | S2 把主播放大再在脸上叠东西，是反例；见第 3 节 |

## 2. 骨架：沿用 示例项目，不重新发明
参考成片：`<素材目录>`（151.6 s，1920×1080，30fps；只读，在云盘上读取慢，抽帧用 `-ss` 跳读）。工程里对应的结构类型：host_full / punch / tag、broll、chapter / big_number / compare / summary 卡、head_flank / keyword / mg 叠层。

2026-10-19 对该片每 7 秒抽一帧（20 帧，`-ss` 跳读）的观察：
- **主播全屏**：约 7/20 帧。出现在两种情形：开场（3 s、10 s、17 s 三个抽样点都是主播全屏，3 s 处带红色大字「LOW」在身后，24 s 才切到 B-roll）；以及中段短促的强调时刻（带身后大字，如「EMPTY」；带故障条纹的转场；一次主播虚化的转场）。
- **B-roll 实景或暗色画布 + 主播圆形小窗（左下，紫色描边）**：约 12/20 帧，是大部分时间的画面。
- **章节标签**：左上角一组小标签（LEVEL 8 / RIGHT / WATCH / ACTION），随章节高亮当前项（绿色）。
- **元素类型**：关键词药丸/大字（实景上的「ANNUAL REPORT SHORTFALLS」框、「$10,090」背景）；实景上的图表（大数字 8 + 一列条形，「LEVEL 8 – LOWEST」）；示意图（示例项目 —— MINING RIGHT 连线 + 三个勾 + 结尾大字「MINING CHARTER」荧光绿）；三栏卡片（BOARD / MANAGEMENT / PROCUREMENT，卡片上有图标圆章和标签）；清单/竖向标注卡（BANKS / INSURERS / EQUITY DEALS 贴在航拍城市上，带竖线）；章节大数字（「3 THINGS TO WATCH」）；引用/手写体斜体字（「tied to」「not a」「Quite」）叠在 B-roll 或主播旁；结尾大字。
- 字幕：底部白字黑底条，逐句。
- 注意：观察是 7 秒间隔的抽样，不是逐段统计；「主播全屏只在短促强调时刻」是用户的说法，抽样显示开场有一段较长的全屏主播，中段才是短促强调，**比例约 35% 全屏、约 60% 小窗/画布，待用户确认口径**（见交回清单）。

## 3. 「融合」的含义（用户口径）
1. **骨架不动**：主播全屏只在短促强调时刻，常配身后大字；大部分时间是 B-roll 实景或暗色画布，主播圆形小窗在左下；章节标签；关键词药丸、实景上的图表、三栏卡片、清单卡、引用大字、结尾大字。
2. **融合 = 把骨架里每个元素的动效和设计升级到新标题字的水准**（标题的缓动、错峰、质感、字体处理），而不是把主播放大再叠东西。
3. **不要做**：主播大画面上叠特效/图形（S2 的做法，被否）；遮脸；把积木当前景盖在主播身上。
4. **要做**：积木当「整屏画布/B-roll 场景」用（暗色画布 + 图表/示意图/卡片），主播小窗在左下；强调时刻主播全屏 + 身后大字（标题字积木）；章节标签和字幕逐元素升级。
5. 沿用 `promo-and-hosted-pipeline.md` 的口播片流程：字幕逐词对齐过 G5.5 闸门；画面零汉字（英文片）；不做 BGM；不加说明性小字。

## 4. 做片检查清单
- 每个 B-roll/画布场景是不是整屏、主播是不是小窗（圆形、左下）？
- 全屏主播是不是只在强调时刻，身后有没有大字？
- 图表、图标是否达到「精美」等级（用户原话「太 low」是对旧版的评价），动效是否沿用已认可的标题字水准？
- 元素有没有遵守 principles 第 15 节（一屏一个焦点、焦点靠亮度和清晰度、屏幕空间暗角、相机不停）？
- 先出整屏静帧给用户看，再渲全片（用户判断快、成本低）。

## 身后大字口径（2026-10-19 S3 复盘后定）
用户看 S3 后指出：开场 LOW、MATTER 的身后大字比 示例项目 原片差。量出来的原因（`<工程目录>/out/behind/NOTES.md`）：S3 为了「读得出」把字缩小、推离头部（LOW 字面积只有 示例项目 的 0.67 倍，MATTER 只有 0.32 倍，几乎不和头重叠），丢了体量和「人在字前」的深度感。口径改为：
- 身后大字默认用 `giantBehind` + 自动布局（`layout_behind.mjs` 预计算，或 `auto` 运行时），**不再手摆 x/y/px**。
- 尺寸：大写字高 0.45–0.52 H（示例项目 0.39–0.41 H）；头可以坐在词的缺口里（LO·[头]·W），或像 示例项目 一样挡住长词中间一个字母；字的墨迹被挡 ≤ 20%，每个词首尾字母被挡 ≤ 15%。
- 重叠是深度线索，不是缺陷：布局在同等字号里优先选被挡约 8% 的位置。
- 规律与数值见 principles.md D9。

## 主播出镜尺度（用户 2026-10-19 拍板）
- 开场 15–20 秒可以让主播全屏建立信任（配身后大字等设计元素）。
- 之后以 B-roll 实景 / 画布为主，主播圆形小窗；中途只在强调句短暂全屏。
- 不要再按“全片主播全屏、往人身上叠东西”的思路做（S2 反例）。

## 中文口播的标题口径（2026-10-20）
用户的视频旁白是汉语；屏幕上的字用中文还是英文，看哪个更合适，中英混排很常见（「什么是 RAG」「LLM 调用 API」）。规则和证据见 principles.md §18、`<工程目录>/out/zh-title/STYLE.md`。
- 设计师标题预设直接写中文（`lang` 默认 'auto'），会自动换成中文字体和排版：标题粗黑用思源黑体 Heavy（横向 0.88）加 Barlow；钩子、问句用思源宋体 Heavy；标签、引导语用得意黑；霓虹用思源黑体 Medium 加暖白。同一画面最多 2 种字体。
- 中英混排时汉字和拉丁字中间不打空格（原片「剪映Hub」），排版器会自动留 0.12 em；英文缩写保持大写（RAG、API、LLM）。
- 标题里不写句末的句号、逗号（排版器会自动删掉），问句保留「？」；数字超过 1 万用「万 / 亿」（`numberStat` 的 `unit:'auto'`）。
- 身后大字：中文词最好 2–4 个字（「幻觉」「胡说八道」「检索增强」），布局交给 `giantBehind` 的中文自动布局（`layout_behind.mjs` 里写 `lang:'zh'`）。6 个字以上的混排短语一行放不大，改成「大字 + 引导语」（例如大字「RAG」、引导语「什么是」）。
- 毛笔字只用于 2–4 个字的情绪词；不对中文用电脑合成的斜体。

## 标题多样性（用户 2026-10-20）
一个视频里要融合多种标题样式，不要反复使用“身后大字/夹头词（giantBehind）”。它好看但只在开场和少数关键强调点用（整片建议 ≤2–3 次）；其余按语境轮换其他设计师预设（sweepThin、outlineFill、serifPair、quoteStack、numberStat、penCircle、neonTube、mirrorMarquee、videoWindow、glyphDissolve、throughObject 等）。做 timeline 时先列“标题样式清单”，相邻两个标题不用同一预设，同一预设整片不超过 2–3 次（数字强调类除外）。

## 人与动效交融（用户 2026-10-20，仅用于技法展示类视频）
用户看 Video1 样片合成后的要求（多轮，最终口径）：**任何时刻画面里都有主播**（不做纯动效、无主播的镜头）；大屏与小窗按 **50 / 50**；小窗要多种样式、有交互，不要千篇一律的圆形小窗；**动效是演出，不是展品**——每个动效服务这句台词，并且和主播发生关系（被他挡、从他身前过、影子落在他身上、由他的手势/声音触发、从他的轮廓里长出来）。这是对上面 示例项目 骨架（主播多数时间圆形小窗）的有意突破，**只用于展示技法的片子**；底线不变：脸上不叠东西、标题样式多样（giantBehind 整片 3 次左右、不相邻）、字幕逐字对齐过 G5.5。实例：工程 `out/video1/STORYBOARD_v3.md`、`RECOMMENDATION.md`、`integration_tests/`（5 张验证静帧 + METHOD.md）。

**alpha 方案（已验证）**
- HeyGen 绿底是合成纯色，用色差键 + 反混合 + 边缘取色延伸，离线一次：`src/video1/integration/key_host.py`（0.36 s/帧）→ VP9 yuva420p WebM（10 s 约 5 MB）+ 每帧 matte PNG（`m_` 含桌面、`mp_` 只有人）+ 手部运动能量 `energy.json`；`scripts/matte_silhouette.py` 出 `silhouette.json` 给身后大字自动布局。不要用 ffmpeg chromakey（暗部发灰、外缘深蓝边），不要在 Remotion 里实时键控（每次渲染都多一倍解码和像素运算）。
- **Remotion 4.0.531 的 `OffthreadVideo transparent` 解 VP9/ProRes 时把暗部压黑**（灰 28→19，8→1；PNG-MOV 不会）：编码前做反曲线（`remotion_vp9_curve.json`），并明确 BT.709 矩阵，否则主播偏暖、发黑，和桌面延伸、背景对不上。升级 Remotion 后用灰阶条重测。

**层级（自下而上，每个镜头相同）**：背景（只吃相机缩放的 0.5×）→ 身后动效 → 主播墙面影子（alpha 的 drop-shadow，画在身后动效之上，大字会被他的影子压暗）→ 主播 alpha → 桌面延伸（画在主播之上，不重叠）→ 落在他身上的东西（用他的 matte 遮罩：身前元素的影子、窗口光、下一场景从他身体里长出）→ 身前动效 → 字幕/HUD（不跟相机）。一个镜头一台相机，包住背景以外的全部世界层；**主播跟着相机走，不固定**，遮挡和投影才对得上。穿过他的元素（卡片环）用「同一个场景函数画两次、按 z 各取一半」，不靠 zIndex。

**主播摆位**：脸中心 (x, y) + 缩放 s（`place.ts`：big 0.50/0.37/1.12、mid 0.50/0.33/0.92、left 0.27/0.36/1.0、right 0.72/0.36/1.0）。身后大字的自动布局必须用同一组摆位算（`layout_behind.mjs` 的 `look = {srcFace, target, scale}`），摆位一改就重跑；中文三字横穿、两字被头分开（缺口）、拉丁词横穿被头挡中间字母——三种布局轮换。身前元素永远在下巴以下；手势区里的身前元素会把抬起的手「切」掉（验证静帧 B），选手放低的时段或只走桌面以下。

**HeyGen 桌面**：木桌是主播层的一部分（全宽）。主播一挪位或缩小就露底，要用同一份解码帧的桌面镜像平铺补左右和下方；桌面是最近的前景面——身后元素的底部消失在桌后（深度线索），身前元素可以落在桌上。

**交互的做法与边界**：手势 = alpha 运动能量的峰（下巴以下、桌面以上的 |Δα| 均值），只能说「这里手动得多」，不识别具体手势，只在关键词 ±6 帧内找峰；手的位置 = matte 手部区域极值点（逐帧、0.1 s 平滑）；声音驱动 = 配音音量包络；他本身被渲染 = GlyphCloud 的 shape 用他的轮廓密度。

**小窗**：小窗是世界里的一个元素（有视差），窗内是整幅大屏画面按覆盖比例裁切、以脸为锚；大屏↔小窗用形态变形（宽、高、圆角各一条弹簧）、遮罩擦除、跨切延续衔接，不硬切。样式清单与用法见 Video1 分镜第 3 节（通话窗、取景框、贴面板边的卡片窗、视差悬浮窗、轨道中心圆窗、网页里的视频位、翻牌网格里的一张、毛玻璃窗、灵动岛胶囊、关注卡头像），同一样式不相邻，圆形小窗只在「圆有含义」时用。

**注意事项**：渲染约 0.38 s/帧（concurrency 2），整片按段渲染再 concat；网页素材一律自制、地址栏写 localhost、不放第三方 logo；先出静帧给用户看再渲动态。
