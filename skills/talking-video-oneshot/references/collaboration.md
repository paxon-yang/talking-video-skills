# 协作规程：每轮交付、怎么提问、反馈怎么改、偏好怎么记

> 目标是"和原片一样精美"，靠一轮一轮对照、改、再对照得到，不是一次生成。流程骨架见 SKILL.md「协作工作流」。
> 本文件的参数改动对照表是**起点**：具体数值以 `<工程目录>/src/tokens.ts` 与 packaging.md / motion-and-camera.md / comfort-rules.md 为准；表里的数值若与它们冲突，以它们为准。

## 1. 每轮交付物清单
| 轮次 | 交给用户看（形式） | 单次数量上限 | 请用户确认 | 存放 |
|---|---|---|---|---|
| 0 素材接收 | 验收表（文字表格）+ 1–3 张抽帧（图）+ 时间戳来源说明 | 3 张图 | 视频用哪条；不合格项是否重导；时间戳方案 | notes.md；`input/` |
| 1 稿子 | 标题/钩子备选（3 行）+ 口播稿全文 + 精简角色表（表格） | 1 份稿 | 钩子选择；删改句；事实/数字是否属实 | `script.md` |
| 2 分镜 | 分镜表（表格，按时间段分页）+ 素材清单（表格） | 20 镜内一次发完；超出分两批 | 节奏；每项素材谁提供/降级 | `storyboard.md` |
| 3 样张 | 左原片右我们的并排图 + 差距清单 | 每批 ≤4 张，总 6–10 张 | 每张 像/不像/哪里不像；优先级 | `review/r3_*.png` |
| 4 预览 | 低清视频 1 条 + 5–8 个重点看时间点 | 1 条 | 逐时间点反馈；整体节奏 | `review/` 与 `out/<slug>/` |
| 5 终版 | final.mp4 + 自检表 + 最后一轮并排帧 | 1 条 + ≤4 张 | 是否交付；遗留项 | `out/<slug>/` |
通用规则：
- 一次只推进一轮；不在用户没确认上一轮前做下一轮的重活（渲染很贵）。
- 文件名带轮次和版本：`r3_cmp_02_v2.png`、`preview_v3.mp4`，改过的不覆盖，用户能说"回到 v2"。
- 每次交付先写一句"这版相比上一版改了什么"。
- 不让用户去读 JSON；给他们看图、视频、表格。timeline 只是我们内部文件。

## 2. 怎么向用户提问
原则：**具体到时间点/镜头号，给 2–3 个选项，允许"都不是，我想要……"**。不问"你觉得怎么样""还有什么要改的"。
| 不要这样问 | 这样问 |
|---|---|
| 钩子你满意吗？ | 开头有三个版本：A「你敢信？……」B「……」C「……」，选哪个？或者哪句要换词？ |
| 节奏合适吗？ | 0:20–0:50 这一段我切了 7 刀，原片同阶段是 4–6 刀。你看预览时是觉得 (a) 太快跟不上 (b) 刚好 (c) 还可以更紧？ |
| 动效好看吗？ | 第 5 镜的对比卡（图 3）：药丸入场我用的 12 帧模糊放大，原片是 6 帧左右横向模糊。想保留现在的柔和感，还是改成和原片一样利落？ |
| 主播位置对吗？ | 圆形 PIP 现在在左下，直径 0.14W。看图 2：(a) 再大一点 (b) 保持 (c) 换到右下 |
| 还要补什么素材？ | 第 9 镜缺「输入需求」的录屏，要 5–10 秒、1080p 以上、光标可见。你能录吗？不能的话我降级成关键词卡 + 主播。 |
规则：一条消息里问题 ≤5 个，按重要性排；能自己对照原片判断的事不问用户（问的是"你想要哪种"，不是"哪种对"）；用户答"随便"就按默认并记入 notes.md 标"默认，未明确确认"。

## 3. 用户反馈 → 参数修改对照表
先复述你理解的问题（"你是觉得 0:41 那一镜同屏东西太多？"），确认后再改。表中"先对照原片"指：找对应原片证据帧并排看，确认差在哪，再动参数。

| 用户常说 | 先确认什么 | 怎么改（起点） | 对应文件 |
|---|---|---|---|
| 太花 / 太乱 | 哪一镜？是东西多还是颜色多 | 同屏文字块降到 ≤3（上限 4）；一屏只留 1 个主标题；强调色降到 ≤2；去掉次要标注/第二个 callout；贴字改成只留 level 2 | comfort-rules（密度、强调色）、packaging |
| 太素 / 太空 | 是哪段静得久 | 补一次录屏标注或推拉；开头 20–30s 补夹头词；章节卡补幽灵字；**不是**加更多动效而是补"证据" | visual-mapping、motion-and-camera |
| 节奏太快 | 哪个时间段；是切得多还是字幕快 | 把 2 个短镜合并成一个主画面（目标 2–3 句 / 4–7s）；该段刀数降到 ≤12/分；停留 ≥40 帧；插一次主播大景 3–6s | comfort-rules（刀/分、主画面长度） |
| 节奏太慢 / 拖 | 哪段 | 开头 20–30s 刀数 ≥5；切点对齐句首；删掉冗余句（回第 1 轮改稿）；录屏每 3–5s 一次推拉/标注 | comfort-rules、hooks-and-copy |
| 不够精致 / 不像原片 | 哪个元素不像（字体？阴影？间距？缓动？） | **必须并排对照原片帧**，逐项查：字体与字重、描边/阴影、圆角、元素间距、网格线色值与 72px、字幕框位置（y≈0.905H）、缓动曲线与时长档（0/6/12/18 帧）；差异来自组件则记录为工程问题 | packaging、`src/tokens.ts`、motion-and-camera |
| 主播太小 | 大景还是 PIP | PIP：换大一档预设（bl_circle → bl_circle_big，或 right_rect_big 右大矩形；预设名见 visual-mapping PIP 预设 / 工程 types.ts PipSpec）；大景：增加主播大景占比、punch-in 1.08；若是原视频里脸太小（脸高 <0.30H）→ 回第 0 轮请用户重导 | visual-mapping、digital-human |
| 主播太大 / 挡东西 | PIP 挡了内容吗？还是大景占比过高 | 改 PIP 预设或关闭 PIP；缩短大景到 3–4s；动效段让位给内容（PIP 只在录屏/对比/图表/数字段开） | visual-mapping |
| 字幕不舒服 | 位置、大小、速度还是样式 | 位置：y 0.905H 全片不变；字号：box 46px；每行 ≤14 字（8–10 最佳）；换行位置按语义断；样式全片只一种；与口播不同步 → 查时间戳（第 0 轮） | packaging、comfort-rules |
| 像 PPT | 是画面静还是切换呆 | 静态素材加线性慢推 1→1.08；插主播回归；贴字跟口播（说到才出现，−2~+4 帧）；录屏加 push 1→1.12（28 帧 inOutCubic）；避免连续 3 张卡片 | motion-and-camera、comfort-rules |
| 动效生硬 / 突兀 | 入场、停留还是退场 | 缓动改 inOutCubic / outCubic；时长用档位（快 6 / 标准 12 / 慢 18 帧）；入场加轻微模糊或位移而不是硬弹；退场硬切即可；不要自创时长 | motion-and-camera |
| 运镜晕 / 推太猛 | 哪一镜 | 幅度 ≤1.12；时长 ≥28 帧；punch-in ≤2 次/分；运镜只作用内容层，PIP/字幕/HUD 不动 | motion-and-camera |
| 贴字对不上嘴 | 早还是晚 | 早 → 入场帧改为关键词开始 +2~+4；晚 → 提前到 −2；若整片偏 → 时间戳整体平移（第 0 轮同步校验） | hooks-and-copy、remotion-pipeline |
| 颜色不对 / 太亮 | 哪个元素 | 对照 packaging 色值（底 #010101、网格 #1A1A1A、强调 #9BF900 / #F8D800 / #FF7A00、红 #F50000 仅钩子）；主色可换成用户自己的色，但数量 ≤3 | packaging |
| 想更像某一位（博主A / 博主B） | 具体想要哪一点 | 博主A：暗底网格、录屏推拉、HUD；博主B：大景回归、静态素材慢推、大数字、图表（图表目前 P2 未实现，用替代方案）；只迁移视觉母题，不抄句子/口号（forbidden.md） | SKILL.md 定位、forbidden |
| 字幕太挤（英文版） | 是一条太长还是换条太快 | 每条 ≤7 词/38 字符（4–6 词最佳），长句拆成多条，每条 1.7–2.5s；删冗余修饰语回第 1 轮改稿；字号不动（46px） | english.md §1、packaging |
| 断行难看（英文版） | 断在介词/冠词后？专名被拆开？ | 按语义断：在从句、and/but、逗号前断；`a/the/of/to` 不放行尾；专名与 `XYZ`、`Level 8` 不拆；每条仍一行 | english.md §1、hooks-and-copy |
| 读音不对（英文版） | 哪个词；缩略词还是数字 | 口播稿里改写成读法（`B-B-B-E-E`、`Level eight`、`ten percent`）；重生成该句音频（整句重做，不拼接）；字幕仍显示原写法；记入 notes.md | english.md §5 |
| 出现中文/乱码方块（英文版） | 哪一帧、哪个元素 | 查 english.md §4 零中文清单；传显式英文 props；字体缺字多为字体回落，记工程问题 | english.md §4 |
| 这段我想删 / 加一段 | 该段的作用 | 回第 1 或 2 轮改稿/分镜；改稿后字数、时长、时间戳、分镜、timeline 都要重对 | — |
| 画面里缺东西（我没有这个素材） | 能否补 | 降级为关键词卡 + 主播，或用 callout/聚光灯指向已有素材的一部分；不编造界面/数据 | visual-mapping |
翻译后在回复里写成"镜头 / 参数 / 旧值 → 新值"，例如：「第 5 镜 compare：药丸入场 12 → 6 帧；第 9 镜 push 终点 1.12 → 1.08」。

## 4. 项目的 notes.md
位置 `<工程目录>/projects/<slug>/notes.md`。每次用户确认或改变决定就追加一条，**开新会话/换模型后先读它**。
```
# <slug> notes
## 基本
- 选题 / 目标时长 / 模板 / 数字人工具 / 路径(A|B) / 主题

## 已确认的决定（日期 · 轮次 · 内容）
- 2026-10-17 · R1 · 钩子选 B「……」
- 2026-10-17 · R2 · 第 9 镜缺录屏，降级为关键词卡

## 用户偏好（本项目）
- 不喜欢红色大字；字幕偏小一点

## 素材状态
| id | 来源 | 状态(待提供/已收/已降级) | 备注(分辨率、隐私检查) |

## 时间戳来源
- sentence 级 / 词级；工具；置信度；校验日期

## 版本记录
- preview_v1：反馈 → 改动…；preview_v2：…

## 待办 / 遗留
```
记录规则：只记用户**明确说了的**，推测写成"（推测，待确认）"；改主意时追加新条而不是删旧条，标"取代 日期·条目"。

## 5. 跨项目偏好回写 Skill
当同一偏好在 2 个项目出现，或用户明说"以后都这样"：
1. 写进最相关的 references 文件末尾的「用户偏好（回写）」小节（没有就新建），格式：`- [2026-10-17 来源: <slug> 第N轮] 偏好内容；对应参数；适用范围`。
2. 若与现有数值冲突，**不要直接覆盖原规则**：写成"用户偏好覆盖项"，保留原规则并注明用户偏好优先。
3. 在 notes.md 对应条目后标"已回写 <文件>"。
4. 只回写偏好与经验，不改 `src/`；发现组件缺陷写成工程问题清单告诉用户。
通用的"像原片"经验（例如某组件哪个参数总要调）也同样回写，并标日期，便于后来核对是否被工程更新取代。

## 6. 常见卡点
- 用户说不出哪里不对 → 发并排图，用选择题（"字体/间距/颜色/动作 哪个最不像"），别要求他描述。
- 用户反馈互相矛盾（又要更丰富又要更干净）→ 指出矛盾，按镜头分别问，并给出各自对应的改法。
- 素材质量不够（模糊录屏）→ 如实说明会影响"像原片"，请求重录，不用后期糊弄。
- 时间戳不准 → 先回第 0 轮核对来源，不靠手调每个贴字。
- 渲染贵 → 先出 still，再出区间，再出整片。
