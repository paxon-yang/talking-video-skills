# 数字人设置与口播稿格式（通用；剪映数字人 / HeyGen / 蝉镜等）

> 本文件也是第 0 轮「数字人视频验收」的标准来源（验收表见 SKILL.md）；用户可以自带视频，也可以先拿稿子去工具生成。
> 用户还没指定数字人工具。本文件写"通用规格"，各工具注意点标"需按工具确认"。
> **构图、背景、机位要在数字人生成阶段定好——后期改不了**（夹头词、PIP、punch-in 都依赖这个构图）。

## 1. 景别与构图（主播在画面中的占比和位置）

| 项 | 默认（博主A构图，教程/测评/观点型） | 数据型备选（博主B 构图） |
|---|---|---|
| 景别 | 固定机位、半身正面，**双手入镜**（手势幅度大是原片"舒服"的一部分） | 同 |
| 脸高 | ≈**0.30H**（约 324px@1080） | ≈0.33H |
| 脸中心 cx | ≈**0.48W**（略偏左） | ≈0.54W |
| 脸中心 cy | ≈**0.34–0.44H**，Remotion 取 0.38 | ≈0.25H（头部空间更少、更贴镜头） |
| 头顶留白 | 约 0.07H 起 | 更少 |
| 夹头词留白 | 左 x 0.03–0.305、右 x 0.667–0.97，y 0.07–0.35：**脸两侧这两块区域保持背景干净，别放手/道具** | |
| 字幕带 | y 0.86–0.93：下部（胸口以下）会被字幕压住，**别把重要手势放在这条带** | |
| PIP 取景 | 圆形 PIP 用同一视频放大 1.8 倍并锚定脸 (0.48, 0.38)，所以脸必须在这个位置附近 | |
| 机位 | 1920×1080、16:9、**30fps 恒定帧率**、固定不动 | |

默认用博主A构图（Remotion `layout.face = {cx .48, cy .38, h .30}`）；只有数据/事件型且想要博主B 的贴近感时才用备选，**整片统一**。

## 2. 背景

- 深色（暗紫 #1C0E39 / #30133E 类，或自选暗单色，平均亮度 Y 42–62）；霓虹/辅助光色与你的主强调色一致。
- **背景不要用原博主的房间**（紫色霓虹房间、粉色闪电灯牌、书柜演播室、沙发霓虹背景）；换成自己的暗色单色或简单场景。
- 烧在视频里最简单；若工具支持绿幕/透明 webm 可留作后期换背景，但**目前 Remotion 渲染器没有换背景的实现**（`HostProps.background` 字段未被组件读取），所以实际只能用烧入背景的视频。
- 背景与网格底（#010101）反差要小，大景切到网格图形镜头时不刺眼。

## 3. 服装与形象

- 纯色深色或灰色上衣，**全片同一造型**；无复杂花纹、细条纹（压缩后闪）。
- 不复制原博主的形象特征（黑 T + 短发；灰卫衣；白条纹衬衫）；用自己的数字人形象。
- 数字人手势少时，用 punch-in（≤2 次/分）和夹头词补偿，别试图靠镜头"晃"出动感。

## 4. 灯光与画质

- 面部均匀、无硬阴影；背景比脸暗 1–2 档（暗底是统一风格的一部分）。
- 导出 ≥1080p；肤色、背景亮度在一条视频内不跳（**一次生成整条口播**，不要分段多次生成再拼）。
- 需按工具确认：能否固定光线/背景种子、能否指定景别。

## 5. 语气与语速

| 项 | 规范 |
|---|---|
| 语速 | **5.0–5.5 字/秒**（含停顿实际 4.5–5）；数字人倍速按 1.0–1.1 调，以**实测**为准（用成片字数 ÷ 时长） |
| 数据型上限 | 6.0 字/秒；类比/情绪段可降到 4.3–4.6 |
| 语气 | 平稳、口语、像在"把事想明白"；问句升调，关键数字放慢一点；不要播音腔 |
| 停顿 | 句中语义停顿 0.3–0.5s；段落转折 ~0.8s；每个数字前后各一个短停顿 |
| 重读 | 每句 ≤1 处，对应关键词（贴字） |
| 手势 | 钩子、转折、总结句用大手势；工具若可选"手势强度"取中高（需按工具确认） |
| 眼神 | 看镜头 |

## 6. 口播稿格式（可直接粘贴进数字人工具）

规则：
- 纯文本，**一句一行**，每句 ≤20 字（不含标点）。
- `/` = 短停顿（0.3–0.5s），`//` = 长停顿（~0.8s），`【】` = 重读（每句 ≤1 处）。
- 数字写**汉字或阿拉伯数字按 TTS 读法**（"90%"写成"百分之九十"更稳；需按工具确认）。
- 英文/产品名需要特殊读法时用括号标读音，粘贴前去掉括号（工具各异，需按工具确认）。
- 文件头写：目标语速 5.0 字/秒、目标时长、总字数。

模板：
```
目标：{T} 秒 / 约 {N} 字 / 语速 5.0 字/秒
---
{句1，含 / 与 【】}
{句2}
...
```
**不要**把 `〔贴字〕`、`role/intent` 标记粘进工具：它们只用于分镜表和 script.json。

## 7. 各工具注意点（均需按工具确认）

| 工具 | 注意点 |
|---|---|
| 剪映数字人 | 文本驱动；导出时记得选 1080p；字幕可直接"识别字幕"；是否支持 `/` 停顿标记需实测；多段生成会有表情/光线跳变，**尽量一次生成整条** |
| HeyGen | 文本或音频驱动；可上传自己的 TTS 音频；有字幕/词级时间戳导出能力需确认；背景可选绿幕；注意导出帧率是否 30 |
| 蝉镜等国内工具 | 多为文本/音频驱动，可导出 SRT；词级时间戳通常没有；背景、景别模板有限，先试出构图是否满足 §1 |
| 音频驱动（任意工具） | **推荐路线**：先用带**词边界**的 TTS 生成音频（得到词级时间戳），再喂给支持"音频驱动口型"的数字人工具，这样 `words.json` confidence=1，贴字不用估算 |

## 8. 从数字人工具要拿到什么（对接 Remotion / 剪映）

| 项 | 要求 | 备注 |
|---|---|---|
| 视频 | 1920×1080、30fps 恒定、h264，一次生成整条口播 | 若不是 30fps：`ffmpeg -i in.mp4 -r 30 -c:v libx264 -crf 16 -g 15 -pix_fmt yuv420p host_full.mp4` |
| 音频 | 单独导出 wav（48k），不含 BGM | **Remotion 全片音轨来自 `assets.hostAudio`**；没有则成片无声。从视频提取：`ffmpeg -i host_full.mp4 -vn -ar 48000 -ac 1 host.wav` |
| PIP 代理 | 480p 版本（可选） | `ffmpeg -i host_full.mp4 -vf scale=854:480 -r 30 -c:v libx264 -crf 24 -g 15 -an host_pip_480.mp4` |
| 字幕 | 至少句级 SRT | 剪映路径直接用 |
| 词级时间戳 | 理想有 | 没有则 §9 |

## 9. 获取词级时间戳（优先级）
1. **TTS 原生词时间戳（最好）**：confidence=1；需实测口型与时间戳的固定偏移。
2. **强制对齐**：工具只给文本驱动 + SRT 时，导出 wav，用已知口播稿做中文强制对齐（WhisperX / stable-ts / FunASR 等）得字级时间戳，再按 marks 合成词。先在样例上验证中文对齐误差（尚未验证）。
3. **句级回退**：只有 SRT 时按字数比例估算词位置，confidence=0.5；贴字偏移改为 **+4 帧**（宁晚勿早）。

## 10. 同步校验
- 音频互相关检查 TTS 音频与数字人视频音轨偏移，>2 帧则全局平移。
- 用语音转写（如 Whisper）转写成片音频，与口播稿对比，防数字人读错字。
- 生成后先抽 5 秒看：脸位置是否在 §1 范围、夹头词区是否干净、手势是否压到字幕带。

## 11. 英文版条目（HeyGen + Fish Audio；详见 english.md §5、§7）
- 语速改用词/秒：2.2–2.6 词/秒（含停顿）；口型由音频驱动，与语言无关。
- 用 Fish Audio 克隆声音生成英文 WAV（PCM 16-bit、单声道、44.1/48kHz），再用 HeyGen 音频驱动生成；先试 10–15s 样片确认口型、读音、语速。上传大小/时长限制**需确认**。
- **关闭 HeyGen 自带字幕与水印**（屏幕零汉字；字幕由 Remotion 出）；导出 1080p/30fps 需确认；背景纯暗色、无文字。
- 口播稿粘贴版：缩略词/数字写成读法，`【】` 去掉，`/` `//` 转标点（见 english.md §5）；`words.json` 来源标明（Fish 词时间戳是否可用需实测）。
- 验收表多加一项：抽帧 OCR 无汉字（english.md §4）。

## 11. HeyGen 实跑结论（示例项目，2026-10-17/18；与上文冲突处以本节为准）
- **音频来源**：用户从不使用 HeyGen TTS；用 Fish Audio 克隆声音生成音频，Claude 在已登录的 Chrome 里操作 HeyGen 做视频。大文件（视频模板）需用户手动拖入；浏览器上传工具只收 <10MB。
- **导出规格**：1920×1080、**25fps**（不是 30）、AAC 48k；关水印、关自带字幕；每次渲染出两个变体，让用户选（整条渲染单变体）。25→30 用帧复制转码。
- **构图实测**（某自建形象）：脸高≈0.25H、中心≈(0.50W, 0.30H)，比 §1 的目标（0.30H, cy 0.38）小而高 → 用 `meta.hostLook.frame`（`srcFace:[.5,.3,.25]`, `scale:1.1`, `target:[.48,.335]`）补偿，不要求重导。
- **背景**：房间是亮的（薰衣草墙+紫灯+书架），用户选保留；用 `hostLook.grade`（亮度 .94、对比 1.06、饱和 .88、冷蓝 soft-light .3、vignette .26、topFade .3）压到与暗卡片协调。HeyGen 背景选项在渲染时固定，改背景 = 重渲（烧积分）。
- **成本**：13s 样片 11 积分；整条 2:31 = 121 积分（≈0.8 积分/秒）。先样片、先定音频，再整条。
- **用户亲自做**：身份验证（新形象需要真人验证，用户可选择跳过，改用已有形象）、付款确认、删除形象/账号。
- **下载**：在页面里点下载（视频与字幕两个 tab），签名链接会过期。
- **时间戳**：下载的 SRT 是句级（首句比音频起点晚约 0.2s）；词级仍需强制对齐（缺）。
