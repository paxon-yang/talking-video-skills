# 示例：一次协作过程——「新手怎么用 AI 整理会议纪要」（教程型，约 90 秒）

> 这是**虚构的协作记录**，用来展示每一轮 Claude 交什么、用户可能怎么反馈、Claude 怎么改。里面的对话、数字（"40 分钟 → 5 分钟"）、素材都是示例，真实项目必须换成用户自己的。
> 完整交付格式见 `../templates/output-template.md`；反馈翻译表见 `../references/collaboration.md`；项目目录见 SKILL.md。
> 项目 slug：`meeting-notes`。工作区 `<工程目录>/projects/meeting-notes/`，渲染用资源 `public/projects/meeting-notes/`。

---

## 第 0 轮 素材接收：用户交来数字人视频
**用户**：我用数字人工具生成了一条 90 秒的视频（`input/host_raw.mp4`），稿子也在里面，帮我按 combo 风格包装。

**Claude 做的**：`ffprobe` 取数据，抽 3 帧（0s / 30s / 70s）看构图，音轨导出 wav 试听。

**Claude 交给用户**：
| 检查项 | 结果 | 说明 |
|---|---|---|
| 分辨率 | ✓ 1920×1080 | |
| 帧率 | ✗ 25fps | 我们转成 30fps（`ffmpeg -r 30`），口型无明显影响，不需重导 |
| 时长 | ✓ 91.4s，一次生成 | |
| 构图 | ✗ 脸高约 0.42H，脸中心约 (0.50W, 0.45H) | 偏大偏低：夹头词区会被脸占掉。**请重导**：景别拉远一档，让脸高约 0.30H、头顶留白约 0.07H |
| 背景 | ✓ 深蓝灰单色 | 亮度合适 |
| 口型 | ✓ 3 个说话帧清晰 | |
| 音频 | △ 带轻音乐 | 请导出"无配乐"版，否则 PIP 与我们的配乐会打架 |
| 时间戳 | 无词级 | 本机没有转写/对齐工具（待搭建）。方案：先用你工具导出的 SRT（句级）出样张；终版前再补对齐 |

**用户**：工具里能调缩放，我重导一版，不带音乐，同时导 SRT。
**Claude 做的**：收到后复检构图（脸高 0.31H ✓），转码到 `public/projects/meeting-notes/host_full.mp4`，提取 `host.wav`，SRT 存 `words.json`（句级，confidence 0.5），notes.md 记："R0 · 视频用 host_v2；时间戳为 SRT 句级，贴字偏移 +4 帧"。

## 第 1 轮 稿子
视频里已有一版台词，Claude 不擅自重写，只给**角色表 + 修改建议**。

**Claude 交给用户**（节选）：
| 句 | 口播 | role | 谁出镜 |
|---|---|---|---|
| s01 | 开会十分钟，整理纪要四十分钟？ | hook | 主播 + 夹头词「四十分钟」 |
| s02 | 其实交给 AI，五分钟就够了 | claim | 主播 |
| s03 | 先把录音转成文字 | evidence | 录屏：上传录音 |
| s05 | 再让它按"结论、待办、负责人"整理 | evidence | 录屏：输入要求 |
| s08 | 我自己试了三场会，平均五分钟 | evidence | 大数字卡 |
| s11 | 你最想整理哪种会议？ | cta | 主播 |
建议：①s08 是"实测数字"，请确认是你的真实数据；②s06 一句 27 字，建议拆成两句；③开头第一句已经是问句，3 秒内成立，保留。钩子备选只给一个替换：「会开完了，纪要谁写？」

**用户反馈**：数字是真的，但是"三场"改成"五场"；s06 拆开可以；钩子不换。
**Claude 改**：改稿 → 字数重算（428 → 436 字，语速 4.9 字/秒，仍在范围）→ 更新 `script.md` 与 notes.md。

## 第 2 轮 分镜 + 素材清单
**Claude 交给用户**（节选，共 18 镜）：
| # | 时间 | 口播 | 画面 | PIP | 动效 |
|---|---|---|---|---|---|
| 1 | 0:00–0:05 | s01–s02 | 主播大景 | 关 | 夹头词「四十分钟」左（红）、「五分钟」右（绿） |
| 5 | 0:21–0:27 | s03 | 录屏：上传录音 | 开 | push 1→1.12，28 帧 |
| 6 | 0:27–0:33 | s05–s06 | 录屏：输入要求 | 开 | callout 框「结论 / 待办 / 负责人」 |
| 12 | 1:05–1:10 | s08 | 大数字「40 分钟 → 5 分钟」 | 开 | 硬切，停留各 2–3s |

**素材清单**：
| id | 用在 | 要什么 | 降级方案 |
|---|---|---|---|
| screen_upload | #5 | 上传录音并出现转写结果的录屏，≥1080p，6–8s，光标可见 | 没有 → 关键词卡「先转文字」+ 主播 |
| screen_prompt | #6 | 输入整理要求并出结果的录屏，6–8s | 同上 |
| result_img | #8 | 整理好的纪要截图（**请先遮掉真实姓名、公司名**） | 没有 → 改用 summary_card |
| logo | #3 | 你用的 AI 工具 Logo（自行确认授权） | 不放，用文字 |

**用户反馈**：两段录屏我可以录；结果截图有，我打码；#12 太早，想放在后面。
**Claude 改**：数字卡后移到 s09 之后，调整相邻镜头，其余不动；notes.md 记素材状态：screen_upload / screen_prompt 待提供、result_img 待提供、logo 不放。素材到后检查分辨率和隐私，再进 `public/projects/meeting-notes/assets/`。

## 第 3 轮 关键帧样张（与原片并排）
素材到齐，Claude 写 `timeline.json` → lint 15/15 → 出 8 张关键帧，每批发 4 张。

**Claude 交给用户**（第一批，图 1–4 都是"左原片 / 右我们"）：
- 图 1 · #1 夹头词：对标 `ex01/ev` 的钩子帧。我看到的差距：我们的「四十分钟」字重偏轻、暗影偏弱；字距略宽。
- 图 2 · #5 录屏 + 圆形 PIP：对标 `v03/evidence/screen_2123.png`。差距：PIP 紫环比原片细；录屏边缘留白一致。
- 图 3 · #6 callout：对标 `ex04/evidence`。差距：虚线圈线宽一致，标签字号小一点。
- 图 4 · #12 大数字：无同类原片帧（已声明），改按 packaging.md 参数核对。
问：每张选 **像 / 不像 / 哪里不像**；优先修哪两处？

**用户反馈**：图 1 差得最多，字不够狠；图 2 紫环我觉得无所谓；图 3 可以。
**Claude 改**：夹头词字重与暗影对照 `tokens.ts` 检查，timeline 层面能调的（字号档位、描边）调整，若是组件本身字重不够（原片字体 vs 工程字体差距，已列在"已知限制"），记录为**工程问题**告诉用户，不改 `src/`。只重出图 1 的 v2 并排图：「字重/暗影 旧 → 新」写在图下。用户确认"这样可以"，notes.md 记："R3 · 夹头词按 v2；紫环保持；工程字体问题待处理"。

## 第 4 轮 低清整片预览
**Claude 做的**：`--crf=32 --scale=0.5` 渲整片（约几分钟，提前告知），输出 `out/meeting-notes/preview_v1.mp4`。

**Claude 交给用户**：preview_v1.mp4 + 请重点看的 6 个时间点：0:00–0:08 开头；0:21 录屏推镜；0:33 章节卡；1:05 大数字；1:18 总结卡；片尾 CTA。
问：逐点告诉我 **OK / 太快 / 太慢 / 别的**。

**用户反馈**：
- 0:21 那个推得有点猛；
- 0:50 左右感觉像在翻 PPT；
- 1:18 总结卡太花。
**Claude 翻译并修改**（对照 collaboration.md §3）：
| 反馈 | 理解 | 改动 |
|---|---|---|
| 0:21 推得猛 | 幅度或时长过 | 第 5 镜 push 终点 1.12 → 1.08，时长 28 → 36 帧，仍 inOutCubic |
| 0:50 像 PPT | 连续三张卡片 | 在第 9 与第 10 镜之间插 3.5s 主播大景（s07 回归）；第 9 镜卡片加线性慢推 1→1.08 |
| 1:18 总结卡太花 | 同屏要素多 | summary_card 三条改两条，去掉图标；强调色 3 → 2 |
确认理解后改，再渲 0:15–0:30、0:45–0:60、1:15–1:25 三段区间出 `preview_v2` 片段，用户看过后再整片。

之后进入第 5 轮：真实时间戳补对齐（若已搭好工具）、lint、终版 `--crf=18`、自检表与最后一轮并排帧交付。任何一步用户想改稿，就回到第 1 轮，只重做受影响的部分。
