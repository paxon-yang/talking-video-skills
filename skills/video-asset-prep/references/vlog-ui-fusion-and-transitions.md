# 技法卡：R1 UI 卡片融进实景 / R2 实景丝滑转场

> 来源：两条抖音热门 vlog 的手机录屏（2026-10-23 入库）。只有录屏，没有原片：画面里叠着抖音界面，分辨率低（R1 560×1280、R2 720×800，30fps），时间是录屏秒数。
> 视频代号：**R1** 香港 vlog（约 14.6 s 一轮循环）；**R2** 重庆雨天 vlog（约 19.5 s 一轮）。两条都是零口播，只有音乐。
> 两条学的东西不一样：**R1 学的是把系统 UI 卡片按镜头透视放进实景、和实景融为一体**；**R2 学的是镜头之间的丝滑转场**。
> 测法：关键帧原分辨率抽图目视；区域位移用相位相关逐帧测（±2–4 px）；帧差找切点。
> 何时读：想把 Claude 界面、对话卡、通知放进实拍 B-roll 时读第一部分；B-roll 段要换镜头时读第二部分。

# 第一部分　R1：UI 卡片融进实景

## 0. 一句话总结

卡片看起来像「真的在那儿」，靠的是五件事同时成立：**内容是本片自己正在放的歌**、**朝向贴合场景的透视**、**跟着镜头动（还带视差）**、**被前景挡住**、**颜色和清晰度跟画面一致**。少一件就会像贴纸。

## 1. 逐镜头记录

| 时间 | 场景 | 卡片 | 怎么融进去 |
|---|---|---|---|
| 0–2 s | 机场、天空 | 歌词小字「我偶尔想回味」 | 小字（约 0.03H）贴在飞机 / 飞鸟旁边，跟着物体 |
| 3.6–4.6 s | 中环街口 | 深色音乐播放卡（歌名「若爱是遗憾 长大才合理」、进度 1:05） | 竖立在马路上，底边顺着路面黄线方向，右端往远处退（左边比右边高约 15%，目视）；鼠标光标点一下，▶ 变成 ‖；双层巴士和蒸汽从卡片**前面**经过，把卡片挡住一部分 |
| 5.0–6.0 s | 天桥栏杆、蒸汽 | 控制中心拆散的模块：播放卡、亮度条、勿扰按钮 | 各模块分开浮在空中，各自转一个角度（偏航约 15–20°，目视）；蒸汽在模块前面，挡住下半截 |
| 6.0–6.7 s | 维港渡轮 | 同一组模块 | 左边的窗柱在卡片前面（遮挡）；模块从上方落进画面 |

| 11.9–12.6 s | 车内仪表盘 | 真实的车机屏幕被换成「Ato · 播放」和歌词「你的发香 说爱我的气息」、粉色封面 | 屏幕替换，跟着镜头移动 |

## 2. 规律

### F1 卡片内容 = 这条片子自己的歌
- 规则：每张卡显示的都是本片背景音乐的歌名、歌词、播放进度，车机屏幕显示的是作者自己的名字「Ato · 播放」。卡片是画面里的「播放器」，不是随便拿来的装饰。
- 证据：R1 3.8 s 播放卡、12 s 车机、7 s 猫旁边的卡片歌词行。
- 置信度：高（画面清楚）。
- 我们怎么用：卡片里放这支片子自己的东西，比如正在讲的那一步、Claude 刚回的那句话、本片标题，不要放无关的界面。

### F2 选一个面，按透视摆
- 规则：卡片先找到它「站在哪」：竖立在马路上（底边顺着路面线条，远端变小），浮在栏杆上方（和栏杆同一个朝向），或者直接替换掉画面里的真实屏幕。
- 数值：街口播放卡左右高度比约 1.15（目视）；天桥模块偏航约 15–20°（目视）。
- 证据：R1 3.8 s、5.4 s、12 s。
- 置信度：中。

### F3 跟着镜头动，而且有视差
- 规则：镜头一动，卡片跟着场景一起动，不是钉在屏幕上；而且位移量介于远景和近景之间，像真的放在某个深度上。
- 数值：R1 3.7–4.4 s 镜头下摇，同样 0.7 s 内：卡片纵向移动 116 px，远处楼群 130 px，近处路面 189 px（相位相关逐帧累计，±4 px）。卡片的位移接近楼群、明显小于路面，说明它被放在中远景的深度。
- 证据：R1 3.7–4.4 s。
- 置信度：中高（实测）。

### F4 被前景挡住（分层）
- 规则：卡片放在「背景」和「前景」之间：巴士、蒸汽、窗柱、栏杆从卡片前面经过或挡住它。这一下遮挡是让人相信它在空间里的关键。
- 证据：R1 4.6 s（巴士 + 蒸汽挡住播放卡）、5.4–6.0 s（蒸汽挡模块下半截）、6.4 s（窗柱在卡片前）。
- 置信度：高（画面清楚）。

### F5 颜色、清晰度跟画面一致
- 规则：卡片是半透明磨砂灰，饱和度和对比度都压低；暗处用深色卡（街口阴影里），亮处用浅灰卡；边缘和画面一样略软，带同样的噪点和压缩感；没有外发光，也没有明显投影。
- 证据：R1 3.8 s（深色卡）vs 5.4 s / 6.9 s（浅灰卡）。
- 置信度：中（目视）。

### F6 卡片自己的动作：落下、摆动、错开
- 规则：模块不是一直挂着，是从画面上方落进来，边落边像叶子一样在 3D 里摆；几个模块各自错开。
- 数值：渡轮镜头里卡片 0.3 s 落下约 210 px（约 0.28H），背景同时几乎不动（≤10 px）；猫镜头里卡片 0.3 s 落下约 210 px 后回弹约 −100 px，同时绕 Z 轴从约 −15° 摆到 0° 再到约 +25°，带透视缩短（说明是 3D 旋转，不是平面旋转）（R1 6.05–6.65 s、6.75–7.55 s，相位相关 + 目视角度）。
- 置信度：位移中；角度低（目视）。

### F7 能「操作」它
- 规则：光标在实景里点卡片上的按钮，卡片状态真的变（▶ → ‖）。观众会把它当成一个能用的东西。
- 证据：R1 3.8 s → 4.6 s。
- 置信度：高。

## 3. 在 Remotion 里怎么复用

1. **卡片用真 DOM 做**（Claude 对话卡、终端窗口、通知、播放器），内容取本片自己的（F1）。磨砂：`backdrop-filter: blur(12px)`，背景半透明灰，不加外发光。
2. **贴在真实平面上**（屏幕、桌面、墙、路面）：`scripts/plane_track.py` 逐帧求单应矩阵 → `scripts/hom_to_css.py` 转成每帧 `matrix3d`；替换实拍屏幕先用 `screen_quad.py` 取四角初值。流程见 `scripts/PLANE_TRACK_PIPELINE.md`。
3. **浮在空中的卡片**（没有平面可贴）：不用逐帧单应。先测整帧镜头位移（相位相关，或 `template_track.py` 跟背景里一块纹理），每帧把这个位移乘一个深度系数（中远景约 0.9，近景 >1）加到卡片位置上，就有了 F3 的视差；朝向用 CSS `perspective` + `rotateX/Y/Z`，透视距离可用 `pose_fit_css3d.py` 从参考帧读出。
4. **遮挡**（F4）：把前景物体做成逐帧 alpha 遮罩放在卡片上层。简单的（栏杆、窗柱、桌沿）手画多边形就行；复杂的（行人、车、蒸汽）用抠像工具出 PNG 序列。拍素材时就挑有前景经过的镜头。
5. **调色**（F5）：卡片加 `filter: saturate(.6) contrast(.85)`，亮度按卡片所在区域的平均亮度调；`blur(0.5–1px)` 让边缘和画面一样软；叠一层和素材同样的噪点。
6. **动作**（F6）：从上方落入约 0.3 s，easeOut，落完小回弹；`rotateZ` 在 ±15–25° 之间慢摆，带一点 `rotateY` 产生透视缩短；多个模块错开出场；停住后继续慢漂（principles X5）。
7. **退场**：只让 UI 层碎成噪点块，约 0.4 s，底下的实景不动。
8. **用在我们的片子里**：横屏口播片的 B-roll 段，比如实拍桌面上立一张 Claude 回复卡，笔记本屏幕换成我们的界面，窗外天空里浮着本片标题的播放卡。一段 B-roll 里 1–3 个模块就够，别堆满。

# 第二部分　R2：实景丝滑转场

## 4. 一句话总结

R2 几乎全是硬切，没有叠化，也没有剪映式特效转场。丝滑来自两件事都不断：**速度不断**（在运动最快的一帧切，下一镜带着同样的速度进来再减速），**视线不断**（观众盯着的东西切前切后在同一位置，或者用画面里本来就有的边扫过去）。

## 5. 切点清单（录屏秒数）

| 切点 | 衔接方式 | 测量 |
|---|---|---|
| 1.90 | **整帧推入**：下一镜从画面下方整张推上来，边界有一条细白线 | 纵向速度 136 → 108 → 84 → 60 → 38 → 24 → 7 px/帧，7 帧（0.23 s）走完约 0.7H，近匀减速 |
| 3.00 | 速度接力：切后画面带着向下的速度进来再减速 | 24 → 21 → 18 → 14 → 10 → 7 → 4 → 0 px/帧，8 帧（0.27 s） |
| 3.90 | 前景遮挡：一片大叶子从右下长进来，挡住人群，叶子后面的背景换掉 | 整帧位移约 0 |
| 5.40 | 点击进入：手点 Dock 上的照片图标，图标处放大成下一镜；前景的手和石墙留着 | 切前匀速 +4 px/帧，切后静止 |
| 8.00 | 速度接力：甩伞在切点最快，下一镜（棚顶边缘）带同样的速度扫进来 | 切前 +7 → 14 → 18 px/帧，切后 46 → 42 → 35 → 28 → 21 → 10 → 4，约 0.3 s |
| 10.50 | 遮挡擦除：笔记本屏幕的竖边当擦除线 | 切点整帧跳一次 |
| 13.67 | **匹配剪**：拿咖啡的手在两镜里同位置同姿势，背景从石板路换成大桥 | 切后向上漂 −32 → −28 → −24 px/帧 |
| 16.13 | 屏幕色闪 | 只有帧差尖峰 |

## 6. 规律

### S1 速度接力：在最快的一帧切
- 规则：出镜头的运动（摇镜、甩手、甩伞）加速到最快，在峰值那一帧切；入镜头带着同方向、同量级的速度进来，再减速停住。
- 数值：入镜头 7–9 帧（0.23–0.3 s）近匀减速到 0；出镜头加速约 0.2 s。
- 证据：R2 3.00、8.00。置信度：中。
- 和已有规则：principles X3「入场带着速度出现」、X9「跨硬切延续」的实景整帧版。
- Remotion：两镜各做位移，出镜 easeIn、入镜 easeOut，切点处速度方向和大小对齐。

### S2 整帧推入
- 规则：下一镜整张从画面边缘推进来，边界一条 1–2 px 细亮线，推到位后 easeOut 停住。替代剪映自带转场。
- 证据：R2 1.90。置信度：中。

### S3 匹配剪：盯住的东西不挪位
- 规则：切点前后，视线焦点（手和杯子）在同一屏幕位置、同样大小，只换背景。
- 证据：R2 13.67。置信度：高。
- 拍法：同一只手拿同一个道具，在不同地点各拍一段，构图对齐；剪辑时用上一镜末帧半透明对位。

### S4 遮挡擦除：用画面里本来就有的边
- 证据：R2 3.90（叶子）、10.50（屏幕竖边）。置信度：中。

### S5 点击进入
- 证据：R2 5.40。Remotion：点 Claude 输出里的图片 / 链接，点下处放大进下一段 B-roll。

### S6 切完不静止
- 停稳后镜头继续反向慢漂（R2 1.90 后 +10～+18 px/帧，3.00 后 −7～−10 px/帧），同 principles X5。

## 7. 反面例子：R2 的金鱼

paxon 的判断（2026-10-23）：金鱼是这条片子的**败笔**。对照第一部分正好能说清为什么：金鱼是贴纸感的 3D 素材，F2–F5 一条都没做到（没有朝向、不跟场景光线、没有遮挡、颜色饱和度和雨天画面不统一）；数量太多（高潮段 15 条以上、盖住约 40% 画面），挡住了转场；和画面内容无关，只是对歌名《美人鱼》的字面联想（违反 F1）。

## 8. 选题和钩子

- 评论和弹幕几乎都是「神级转场 / 百万剪辑 / 剪得太好看了 / 出模板吧哥」：观众来夸、来要同款。
- 数据形状（估计，两条样本）：转发 / 点赞 18–21%，收藏 / 点赞 8–10%，评论 / 点赞 0.4–2.4%。技法展示类带的是转发和收藏。
- 候选第 ⑧ 个「想」：**想要同款 / 想学会**。置信度低，待验证。
- 给我们的选题：「我让 Claude 把界面做进了现实」：开头放成品（② 看结果），中段原片和复刻并排（④ 辨真伪），结尾「要模板的扣 1」（⑧ 想要同款）。
- 复刻只作内部学习，不进成片。
