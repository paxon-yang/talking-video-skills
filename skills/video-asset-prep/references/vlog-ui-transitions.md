# 技法卡：实景 vlog 里「屏幕 UI 与实景互穿」的转场（R1 / R2）

> 来源：两条抖音热门卡点 vlog 的手机录屏（2026-10-23 入库）。只有录屏，没有原片：画面里叠着抖音界面，分辨率低（R1 560×1280、R2 720×800，30fps），时间是录屏秒数。数值多为逐帧目视或帧差测得，置信度按 principles.md 的口径标。
> 视频代号：**R1** 城市 vlog（香港，约 14.6 s 一轮循环，抒情歌）；**R2** 城市 vlog（重庆雨天，约 19.5 s 一轮，歌曲《美人鱼》）。两条都是零口播、纯音乐 + 歌词小字。
> 何时读：想在实景 B-roll 段里加「不花哨但被叫神级」的转场时；做 AI 工具片、要把界面放进现实画面时。

## 0. 总结（一句话）

两条片子的「神级转场」不是靠特效库，而是靠**同一个东西跨镜头存在**：要么是一个界面元素（播放器卡片、控制中心滑块、App 图标）住进现实里，要么是一个主题物件（金鱼、飞鸟）从这个镜头游到下一个镜头。观众看到的是「画面之间被一样东西缝起来了」，所以觉得丝滑、高级。

## 2. 技法逐条（规则 → 数值 → 证据）

### T1 界面元素住进现实（UI-in-world）
- 规则：手机 / 电脑的系统界面元素（音乐播放卡、音量和亮度滑块、控制中心按钮）**单独抠出来**，贴在实景里的某个平面上，跟着镜头一起动（平面跟踪），像真的立在街上、浮在猫旁边。界面是同一套，场景在换，界面就成了跨镜头的线。
- 数值：播放卡宽约 0.75W（R1 18 s 处街景）；滑块是竖条胶囊，2–3 个错位排列；界面有轻微透视，不正对镜头；每次出现停留约 1.5–3 s。
- 证据：R1 3.6–8.6 s（街口 → 巴士 → 海边 → 猫），R1 18 s。
- 置信度：中（目视）。
- 我们怎么做：已有 `scripts/plane_track.py`、`screen_quad.py`、`hom_to_css.py`（平面跟踪 → CSS matrix3d），可以直接把 Claude 对话卡、终端窗口、通知贴进实景 B-roll。

### T2 界面退场 = 块状故障溶解（不是整屏故障）
- 规则：界面元素离场时，**只有界面本身**碎成彩色噪点块，同时向下一个镜头淡掉；底下的实景不故障。下一镜头里常有竖条切片露出（像百叶窗拉开）。
- 数值：从完整到消失约 0.4 s（R1 7.5–7.9 s，12 帧）；噪点块是界面的外轮廓（圆角矩形），内部是彩色横纹。
- 证据：R1 7.5–8.1 s（猫 → 冰杯）。
- 置信度：中。
- 与已有规则：principles §6「故障条纹诞生」是整屏按行切片；这里是**局部、只作用在 UI 层**的版本。jianying-guide 写过「不用故障转场」，指的是整屏；局部用在 UI 退场不冲突。

### T3 点进去 = 下一个镜头（点击即转场）
- 规则：手在笔记本上点一个 Dock 图标（照片 App），点下的瞬间图标处放大成下一个镜头；前景的手、咖啡杯、石墙**留着不动**，只把背后的屏幕区域换成新场景，过 0.5–1 s 再把前景也换掉。
- 数值：点击 → 新镜头填满约 0.25–0.5 s（R2 5.1–5.6 s）；前景保留约 1.5 s 后才被新场景的建筑从下往上「长出来」盖住（R2 6.4–7.0 s）。
- 证据：R2 4.6–7.0 s（Dock → 桥 → 洪崖洞）。
- 置信度：中。
- 与已有规则：是 principles §1「下一屏的背景就是上一屏的某个物体」在实景里的版本；我们的 AI 片可以直接用——点 Claude 输出里的一张图 / 一个链接，点下去就是下一段 B-roll。

### T4 分层换景：前景当锚点，背景先换
- 规则：一次转场拆成两步——先换背景、前景（手、栏杆、屋顶、伞）留住；再换前景。观众的眼睛被留住的前景拴着，所以不觉得跳。
- 数值：两步间隔 0.5–1.5 s；新前景用遮罩从画面边缘长出（R2 洪崖洞建筑从下往上，约 0.5 s）。
- 证据：R2 5.6–7.0 s；R2 16–17 s（手机 + 云团留住，背景从桥换成笔记本屏幕）。
- 置信度：中。

### T5 主题物件贯穿（意象接力）
- 规则：选一个和歌名 / 主题对得上的物件（R2《美人鱼》→ 金鱼；R1 → 飞鸟、飞机），让它在多个镜头里出现、从屏幕里游出来、越来越多，最后铺满画面当高潮。形状相似的物体直接互换（飞机 ↔ 飞鸟，同位置同方向）。
- 数值：R2 金鱼第一次出现在 1.0 s（第一秒内就上奇观）；高潮段 16–19 s 金鱼数量从 3–4 条涨到 15 条以上、盖住约 40% 画面；R1 飞机 → 鸟在 1.07 s 同位置互换。
- 证据：R2 1.0–3.6 s、16–19.5 s；R1 0.6–1.4 s。
- 置信度：中。
- 我们怎么做：给一支片子定一个「贯穿物」（例如 Claude 的橙色星芒、一张纸、一个光标），从主播身边飞到 B-roll 里再飞回界面，比每段换一种转场更统一。

### T6 屏幕里出东西（破屏）
- 规则：手机屏幕里冒出云团 / 金鱼，越过屏幕边框进入现实；屏幕内容和现实之间没有边界。
- 数值：云团从屏幕中心长到约屏幕宽 1.2 倍，约 0.75 s（R2 14.5–15.3 s）；随后金鱼从云里游出、带一次 UI 噪点块溶解（R2 15.8 s）。
- 证据：R2 14.3–16.3 s。
- 置信度：中低（录屏太糊，云团大小目视）。

### T7 歌词关键词做成「场景里的字」
- 规则：不在画面上压字幕，而是把歌词关键词做成场景里的物体——笔记本屏幕上的 3D 大字「视而不见」，或者小字贴在物体旁边（R1「我偶尔想回味」贴在飞机旁）。
- 数值：R2 屏幕大字约占屏幕宽 70%，白字蓝底带立体厚度；R1 歌词字高约 0.03H。
- 证据：R2 9–10 s；R1 0–2 s、14 s。
- 置信度：高（画面清楚）。
- 与我们的规则：口播片仍以白胶囊字幕为主；但「关键词卡」可以借这个做法——把关键词放进 B-roll 里的屏幕、白板、纸上，而不是浮在最上层。

## 3. 选题和钩子（对照「观众七个想」）

- **第一秒就出奇观**：R2 1.0 s 金鱼出现，R1 第一个镜头就有歌词 + 飞机，3.6 s 内界面卡片出现。零口播的片子靠画面本身当钩子，对应七个想里的 ② 看结果（「这是怎么做到的」）。
- **评论区信号**：弹幕和评论几乎都是「神级转场 / 百万剪辑 / 剪得太好看了 / 技术流依然吃香 / 出模板吧哥 / 这不去影视飓风上班吗」。观众不是来争论的，是来**夸 + 要同款**的。
- **数据形状**（估计，只有两条）：转发 / 点赞约 18–21%，收藏 / 点赞约 8–10%，评论 / 点赞只有 0.4–2.4%。技法展示类片子带的是转发和收藏，不是评论。
- **补到七个想的一条候选**：⑧ **想要同款 / 想学会**——看到做不出来的好东西，想收藏下来、转给会剪的朋友、在评论区求模板。和 ⑥ 带入自己相近，但动作是收藏 + 转发 + 求教程。置信度：低（两条样本），等我们自己的片子验证。
- **给我们的选题**：「我让 Claude 复刻了抖音百万剪辑的神级转场」——开头放复刻成品（② 看结果），中段原片 vs 复刻并排让观众猜（④ 辨真伪），结尾「评论区要模板的扣 1」（⑧ 想要同款），正好接住这类片子评论区的需求。

## 4. 不照搬的地方

- 两条都是竖屏、零口播、靠歌曲情绪；我们是横屏口播讲解。直接搬整套会变成「数字人 + 一堆特效」，违背偏好。只借**结构**（跨镜头的线、点击即转场、分层换景、贯穿物、场景里的字），每支片子挑 1–2 个用在 B-roll 段。
- 金鱼铺满全屏这种高潮只适合结尾或一个强调点，全片最多一次（principles §8「光和影只给一个主角时刻」同理）。
