# 实战手册：把 UI 和艺术字「做进」实拍画面（现实变成界面）

> 来源：2026-10-23 至 10-24 用 Netflix Open Content 实拍素材连做的 9 版融合练习。前 8 版被逐版否掉，第 9 版用户评价「好多了」。本文记的是第 9 版的思路、做法，以及前 8 版换来的教训。
> 何时读：要把卡片、标注、艺术字、转场放进实拍镜头，并且要求「炫酷 + 完美融入」的时候。技法卡 `vlog-ui-fusion-and-transitions.md` 讲的是参考片里的规律，本文讲的是我们自己怎么做出来。
> 工具：Python + OpenCV 逐帧合成（numpy、scipy、PIL），字体用本机 TTF。不依赖任何积木源码，积木库里的标题预设可选用。

---

## 0. 一句话总结

**不要往画面上贴东西，要让画面里的东西自己变成界面。** 每个镜头只做一个「现实被改写」的动作，比如冻结后被测量、车厢变成玻璃、字母从路牌上飞走、字从海里升起。每个 UI 元素都要同时满足五项融合检查：位置、遮挡、光线、运动、出入场有动机。镜头之间的转场也要用画面里本来就有的东西来完成。

## 1. 九版换来的教训（按用户原话归纳）

| 版本 | 用户评价 | 结论 |
|---|---|---|
| v2 | 「太拉胯，完全不自然」 | 正对镜头的半透明灰卡等于贴纸。先把卡片质感和光影做好，再谈跟踪 |
| v3 | UI 凭空出现，没融进场景 | 每个元素都要有落点（立在路面、被前景挡住），进场要由画面里的动作触发 |
| v4 | 形式太单一，小字普通 | 不要只用卡片，要有艺术字大标题、叠底，字和场景前后穿插 |
| v7 | 好多了，但仍然生硬，不跟镜头动 | 元素必须跟着镜头和场景动（虚拟运镜、视差、被风带走），不能原地淡入淡出 |
| v8 | 太简单，思维要跳跃，不需要一首歌贯穿 | 不再用叙事线串联，**每镜一个出人意料的改写动作**，直接做炫酷 |
| v9 | 好多了 | 本文的做法 |

被推翻的旧结论：技法卡 F1「卡片内容 = 本片自己的歌」只适合安静的 vlog 风格。用户要「炫酷」时，硬套一首歌贯穿全片反而显得小气。

## 2. 流程（顺序不能乱）

1. **先出设计方案，等用户审批后再动手。** 方案写清每个镜头的「改写动作」、元素怎么融入、镜头之间怎么转场、音效清单，并自查五项融合检查。用户明确要求过「设计完让我审批，再动手」。
2. **先做风险点的单帧样稿。** 挑最可能做不出来的两三处（比如分层视差、抠字母、水面文字），各渲几帧自己检查，过了再做全片。
3. **按镜头写脚本，每个镜头一个 `sN.py`。** 对外提供 `comp(k, frame)`，带参数时只渲指定帧到 `chk/` 做抽查，不带参数时渲整段 PNG 序列。四个镜头可以并行渲染（4 核约 6 秒一帧）。
4. **音效脚本直接 import 镜头脚本里的时间常量**（标注弹出帧、打字起点），保证声画对齐。
5. **拼接时加转场**，用 ffmpeg 编码，目标 ≤15 MB（18 秒 1080p，码率 5.8 Mbps，AAC 128k）。
6. **交付前做抽帧拼图**，每个镜头、每个转场点前后各取一帧，重点看衔接是否对得上。

## 3. 五项融合检查（每个元素都要过一遍）

| 检查项 | 问自己 | 做法 |
|---|---|---|
| 位置 | 它立在哪个面上？ | 贴在路面、车厢侧面、路牌斜面、海平面，用单应或分层视差算出位置 |
| 遮挡 | 谁在它前面？ | 天空抠像、净背景板差分、手画多边形，前景压在 UI 上面 |
| 光线 | 颜色、亮度跟画面一致吗？ | 取画面环境色混合 10–15%，加受光边、烟色、折射，整片统一调色 |
| 运动 | 镜头动的时候它跟着动吗？ | 按所在深度给视差系数；跟踪单应；被风或浪带走 |
| 出入场 | 它为什么出现、为什么消失？ | 冻结时弹出，被浪打散，被拖尾带走，嵌回原位 |

## 4. 第 9 版四个镜头的技法

### A. 时间冻结 + 2.5D 分层视差 + 车辆测速标注（高速路）

- **净背景板**：对整段素材逐像素取中值，得到没有车的空路面。
- **车辆分层**：用 MiDaS 单目深度按分位数切层，结果不可靠，同一辆货车会被切开，平移时出现裂缝。**改成手画每辆车的多边形**，与运动蒙版（`|帧 - 背景板| > 0.10`，闭运算 25 后填洞）求交集。按「远到近」排序，近的车抢走重叠区域。
- **被挡住的部分要补**：远层被近层挡住的区域用 `cv2.inpaint`（Telea）补色，并把 alpha 扩进去。这样平移时露出来的是补过的车身，而不是空洞。
- **视差系数按接地点的行号算**：`par(y) = 0.12（y < 520 的远景）`，否则 `0.30 + 0.70·((y-520)/560)^1.2`。背景板逐行按 `dx·par(y)` 重映射，每辆车按自己接地点的系数整体平移，车轮会一直粘在路面上。逐行水平平移不会产生空洞。
- **镜头**：先整体放大 1.12 留出边距，再在 88 帧内缓动横移 dx 0→-100，同时慢推到 1.18，加一点手持晃动。
- **标注**：角标框从 1.25 倍收拢落位（7 帧）。标签逐字打出（每字 1 帧，配打字声），测速数字从 0 滚到目标值（14 帧）。标注层跟着所属车辆一起平移。路面网格先画在背景板空间里，再跟背景板一起做行视差，所以会被车辆挡住。解冻时标注向一侧拖出 6 层残影并淡出。
- **冻结的感觉**：冻结那一帧加 0.35 白闪（时间常数 2.5 帧），降饱和 28%，再配「吸气 + 咔」的音效。

### B. 实物变成玻璃窗口，再钻进去转场（货车车厢）

- 车厢四角在冻结帧上量出来，做成四边形，内部腐蚀 15 px，留出车厢框边。
- 从左到右扫描成玻璃，扫描线处加亮边。玻璃里是净背景板（按车后深度取视差 0.45）高斯模糊 1.6 后压成烟色（×0.66），加两条随横移漂动的斜向反光，顶边一道高光。
- 大字用单应贴在车厢平面上（顶边有透视斜度）。打字的小标也在玻璃上。
- **转场**：玻璃区域在屏幕空间里逐渐透出下一镜的第一帧（缩放 1.12→1.0），镜头从 z 1.18 指数式推到 4.2，钻进车厢，最后几帧强制整屏切成下一镜。标题随推进放大，在 150–160 帧淡出。
- 坑：下一镜的帧要用**未调色**的版本，否则整帧调色时会被调两次。

### C. 实景文字剥离、飞走、再重组（路牌 BIENVENIDOS → 欢迎光临）

- 逐个精确抠出手绘字母做不到：笔画有灰有黑，阈值只能抓到碎片。**改成整块切**：沿路牌斜带建坐标系（u 沿带，v 垂直于带），把整条带拉直成一张贴图，再等分成 11 块木块。
- 木块飞走后，原位置留下深色凹槽（顶边加内阴影），看上去像真的被拔出来。
- 飞行：先弹出 7 帧（朝镜头抬起，rx -28°，带投影），再沿贝塞尔曲线飞到鸟群中心，同时翻滚（rz、ry 正弦变化）。深度越远缩得越小；缩到 0.85 倍以下时用天空抠像做遮挡，飞进柳树后面就被树枝挡住。
- 重组：四块新木块用**原路牌白漆的质感**（亮像素中值色加上原贴图的高频细节，字母处的细节压掉），字用思源黑 900，干笔边缘做法是给字形 alpha 加噪声。木块从鸟群飞回，带 6 帧过冲砸进凹槽，配木头敲击声和低频闷响。
- 出镜：沿路牌斜度方向甩切（速度接力，每帧位移 18→240 px 递增，加方向模糊），接到下一镜。

### D. 海面 3D 大字：升起、浮动、折射、倒影、被浪打散（码头）

- 跟踪：码头单应。镜头只有摇和俯仰，所以同一个单应也适用于海面。字放在参考帧坐标里的水线位置，逐帧映射。
- 3D 字：PIL 渲染字形，往右下方叠 24 层并逐层压暗作为侧面，正面奶油色加纵向渐变，边缘加受光高光。
- 升起：每个字错开 6 帧从水下冒出，16 帧缓出，带一次小回弹。溅水用椭圆环扩散加接触白线。
- 浮动：上下 ±7 px，旋转 ±2.2°，每个字相位不同。
- 水线以下：水下部分横向正弦扰动、混入 60% 模糊水色、透明度 0.35。水面倒影：以水线为轴镜像，用水面亮度梯度做横向涟漪，纵向模糊 6，透明度 0.42，并随距离衰减。
- 浪花遮挡：亮且低饱和的像素当作浪花蒙版，盖住水线附近的字。
- 打散：用多倍频程（fbm）噪声做阈值，从底部往上吃掉字，边缘发白像泡沫。被吃掉的位置放出水花粒子：先向上抛再落下，16 帧内淡出。不要用方块噪声，那样很像数码马赛克。

### E. 结尾：拉远，原来一直在手机里放（反转收尾）

- 本来计划把画面折纸飞进手机，后来改成更顺的拉远：上一镜最后一帧的画面就是手机桌面的大组件，镜头从组件铺满全屏（z ≈ 4.87）用对数插值拉到 1，组件圆角从 0 渐变到 24。
- 旁边两个小组件循环播放前面的镜头（冻结车厢、欢迎光临），奶白纸色背景，深色机身，投影柔和。
- 右侧用打字机效果打出大标题「现实，即界面」（每字 3 帧，带光标闪烁），下面一行橙色等宽英文逐字打出，最后画一条下划线。每个字都配打字声。

## 5. 通用零件

- **天空抠像**：`亮度 ∈ [0.40, 0.52] 平滑 × (B-R) ∈ [0.03, 0.07] 平滑`，阈值按片子调。要先测天空的 B-R 实际值，比如高速路片约 0.19。
- **虚拟相机**：整帧仿射（缩放加平移），速度快时用 3–5 个子帧平均做运动模糊。俯冲阶段子帧间隔要缩到 0.25 帧，否则字会出现重影。
- **调色**：全片统一降饱和到 0.86，微暖，抬黑。合成时都先用未调色的素材，最后统一调一次。
- **音效**（无 BGM，全部用 numpy 合成）：冻结（反向气声 + 咔哒 + 低频闷响）、标注弹出（pop）、每个字的打字声、玻璃闪光（高频闪烁）、木块敲击、翅膀扑簌、出水（滤波噪声 + 气泡）、浪拍（低频噪声包络）、甩切（呼啸）。
- **常见坑**：Remotion 在云端渲染中文字体前，要先把字体下载到本地 `public/`，否则 Chromium 会超时。PIL 画出来的数组是按 BGR 顺序交给 OpenCV 的，所以颜色也要按 BGR 写，否则橙色会变成蓝色。有些素材 `cap.set` 跳到末尾会读空，要改成顺序读取。

## 6. 交付前检查表

- [ ] 每个元素都过了五项融合检查，没有原地淡入淡出的
- [ ] 每个镜头有一个「改写现实」的动作，没有为了串联而硬加的叙事线
- [ ] 转场借用画面里的东西（玻璃、路牌斜线、浪、手机组件），前后两帧对得上
- [ ] 打字的地方都有打字机动画和打字声；没有 BGM、没有紫色霓虹、没有宋体；整体淡雅，橙色只少量点缀
- [ ] mp4 ≤ 15 MB，放到网页上可以播放和下载
