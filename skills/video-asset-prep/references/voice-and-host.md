# 声音与数字人备料（实测经验）

## 第一部分 声音
1. 用自己的克隆声音，在配音工具里生成；不用数字人工具自带的 TTS。
2. 稿子按「读法」改写：缩写写成逐字母（`A I`），否则会读成词；数字、年份按口语写；先生成 10–15 秒样音听读音。
3. 近音字（件/点）、多音字、儿化（活儿）听完逐句核对；错了只重录那一句。
4. 后处理：静音封顶到 0.40–0.45 s（TTS 常在句间留 1 s 以上空白）；速度 ≤1.2 倍人声基本不失真；拼接在停顿中点，12 ms 淡入淡出，两段响度差 ≤1.5 dB；拼完重做对齐。
5. 定稿后不再改音频：数字人要重渲、烧积分。
6. 逐词对齐：mlx-whisper（turbo-q4）+ 稿子文字为准；识别器对气声有偏差，以波形起音为准核字幕（`pipeline-scripts/wave_onset_check.py`）。

## 第二部分 数字人
1. **选形象**：自拍形象或工具里的形象均可；有的形象需要真人身份验证，只能用户本人做。
2. **生成**：音频驱动；**用形象自带的背景，不选绿幕、不抠像**（用户铁律，2026-10-25）；1080p、关水印、关自带字幕。整条约 0.8 积分/秒，样片（10–15 秒）通过再渲整条。上传音频后会新增一个场景，先删旧场景再生成。
3. **抠像**：不做（用户铁律）。旧做法（色差键 key_host.py → VP9 alpha）只留作参考，不再使用。
4. **解码曲线**：Remotion 的透明视频解码会压黑暗部，编码前做反曲线（`remotion_vp9_curve.json`）并明确 BT.709，否则主播偏暖发黑。
5. **清晰度**：数字人源片偏软是常态。先测（拉普拉斯方差：原片 / 抠后 / 成片）再判断；可选只对亮度做的轻锐化（alpha 内收 3 px，限幅），放大 ≤1.05。
6. **口型**：数字人口型通常略晚于声音，主播层整体提前 2–3 帧（`lead_era_v3.py` 用句首起音事件平均来量）。
7. **桌面 / 摆位**：桌面是主播层的一部分，主播挪位或缩小会露底，需用同帧镜像补；摆位用「脸中心 + 缩放」统一参数，身后大字的自动布局用同一组参数。
8. **验收**：嘴型清晰、无糊脸、手不变形；脸亮背景暗；抠像帧数与视频一致。
